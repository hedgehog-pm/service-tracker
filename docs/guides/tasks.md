# Работа с задачами и проектами

## Изменить описание, приоритет или срок {#update-task}

Перед обновлением получите текущие значения полей задачи, которые хотите сохранить:

```sh title="GET /projects/1/tasks/1"
curl http://localhost:8080/projects/1/tasks/1
```

Для выбора нового приоритета запросите доступные приоритеты проекта:

```sh title="GET /projects/1/priorities"
curl http://localhost:8080/projects/1/priorities
```

Выберите приоритет из `items` и передайте его `id` в поле `priority_id`.
Оценку в `estimate_seconds` передают в секундах, а срок в `due_date` — датой в формате `YYYY-MM-DD`.

Следующий запрос назначает приоритет `High`, добавляет описание,
оценку в один час и срок 30 ноября 2026 года.

```sh title="PUT /projects/1/tasks/1"
curl --request PUT http://localhost:8080/projects/1/tasks/1 --json '{
  "title": "Добавить фильтр по цене",
  "description": "Покупатель задаёт минимальную и максимальную цену.",
  "priority_id": 4,
  "module_id": null,
  "estimate_seconds": 3600,
  "due_date": "2026-11-30"
}'
```

В ответе `200 OK` проверьте изменённые поля.

!!! note "Обновление заменяет поля целиком"

    `PUT` требует `title`, `description`, `priority_id` и `module_id`.
    Оценку и срок тоже нужно передать заново в `estimate_seconds` и `due_date`,
    если вы хотите их сохранить: пропущенные поля станут `null`.

    Для снятия привязки к модулю передайте `module_id: null`.
    Таким же значением `null` можно убрать оценку или срок,
    а для очистки описания нужна пустая строка.

Редактирование сохраняет ключ, тип и проект задачи.
Её статус меняют отдельным действием.

## Учесть выполненную работу {#worklogs}

Чтобы записать время, потраченное на задачу, добавьте отдельную запись трудозатрат.
Укажите начало работы в `started_at` с часовым поясом
и её длительность в секундах в `time_spent_seconds`.
Комментарий необязателен.

```sh title="POST /projects/1/tasks/1/worklogs"
curl http://localhost:8080/projects/1/tasks/1/worklogs --json '{
  "started_at": "2026-11-14T09:00:00+07:00",
  "time_spent_seconds": 7200,
  "comment": "Исправление фильтра товаров"
}'
```

Ответ `201 Created` содержит запись с её `id`.
Следующий такой запрос добавит ещё одну запись,
поэтому выполненную в разное время работу можно учитывать по отдельности.
При этом оценка задачи в `estimate_seconds` сохраняется.

Чтобы получить журнал работ, запросите список записей:

```sh title="GET /projects/1/tasks/1/worklogs"
curl 'http://localhost:8080/projects/1/tasks/1/worklogs?limit=50&offset=0'
```

В `items` записи упорядочены по убыванию даты начала работы.
При одинаковой дате первой идёт запись с большим `id`.
Поле `total_time_spent_seconds` содержит сумму времени по всем записям задачи,
поэтому итог остаётся полным при чтении отдельных страниц и пустой страницы в конце списка.

Для исправления записи отправьте `PUT /projects/{project_id}/tasks/{task_id}/worklogs/{worklog_id}`
с новыми `started_at`, `time_spent_seconds` и `comment`.
Нужно передать все три поля. Чтобы убрать комментарий, задайте `comment: null`.
После обновления запись сохраняет свой `id`, задачу и время создания.

Для удаления используйте `DELETE` по тому же адресу.
Удалённая запись перестанет учитываться в общей сумме трудозатрат задачи.

## Сменить статус {#change-status}

1. Получите `GET /projects/{project_id}/tasks/{task_id}/transitions`.
2. Выберите действие из `items` по названию и целевому статусу `to`.
3. Отправьте его `id` в поле `transition_id`
   методом `POST` на тот же адрес.
4. Проверьте новый `status_id` в возвращённой задаче.

Выбирайте переход из списка действий самой задачи.
Именно этот список учитывает её текущее состояние,
тогда как справочник статусов проекта содержит все используемые в проекте статусы.
Пошаговый пример есть в [быстром старте](../quick-start.md).

Доступность переходов может измениться после получения списка.
Если запрос вернул `409 Conflict`, снова прочитайте задачу и её переходы,
затем выберите действие для актуального состояния.

## Сгруппировать задачи по модулям {#modules}

Создайте модуль в нужном проекте:

```sh title="POST /projects/1/modules"
curl http://localhost:8080/projects/1/modules --json '{
  "name": "Каталог"
}'
```

В ответе `201 Created` вернётся модуль с его `id`.
Чтобы включить в него задачу, передайте этот идентификатор в `module_id`
при её создании или обновлении.
При обновлении также сохраните остальные редактируемые поля, как описано в
[инструкции по изменению задачи](#update-task).

Чтобы получить список модулей, выполните запрос:

```sh title="GET /projects/1/modules"
curl http://localhost:8080/projects/1/modules
```

Чтобы переименовать модуль, отправьте `PUT /projects/{project_id}/modules/{module_id}`
с новым `name`. Такое изменение сохраняет все задачи в модуле.

## Найти задачи по условиям {#find-tasks}

В списке задач проекта можно отобрать задачи по статусу, модулю, типу и приоритету.
Значения для фильтров берутся из справочников этого проекта.

| Фильтр | Как выбрать значение |
| --- | --- |
| `status_id` | Получить статусы проекта через `GET /projects/{project_id}/statuses` |
| `module_id` | Выбрать модуль из `GET /projects/{project_id}/modules` |
| `task_type_id` | Выбрать тип из `GET /projects/{project_id}/task-types` |
| `priority_id` | Выбрать приоритет из `GET /projects/{project_id}/priorities` |

Запрос отбирает задачи в статусе `In Progress` с приоритетом `High`.

```sh title="GET /projects/1/tasks"
curl 'http://localhost:8080/projects/1/tasks?status_id=2&priority_id=4'
```

В результат попадают только задачи, которые соответствуют всем переданным фильтрам.
В `items` они возвращаются по возрастанию номера внутри проекта.
Если на странице нет подходящих задач, массив будет пустым.

Списки проектов, задач, модулей, досок и записей трудозатрат поддерживают постраничную выдачу:

- `limit` — размер страницы от 1 до 200, по умолчанию 50.
- `offset` — число пропущенных записей, по умолчанию 0.

Для следующей страницы увеличьте `offset` на `limit`.
Общее количество записей в ответе не возвращается,
поэтому конец выдачи определяют по странице, на которой элементов меньше `limit`.
Пока вы читаете страницы, другие запросы могут менять состав списка.

Для задач в колонках доски используется [выдача с курсором](boards.md#column-tasks).

## Переименовать проект {#rename-project}

```sh title="PUT /projects/1"
curl --request PUT http://localhost:8080/projects/1 --json '{
  "name": "Интернет-витрина"
}'
```

В ответе вы получите проект с новым названием и прежним ключом.
Ключи его задач также сохранятся.

## Удалить задачу, модуль или проект {#delete}

| Объект | Метод | Результат |
| --- | --- | --- |
| Задача | `DELETE /projects/{project_id}/tasks/{task_id}` | Задача удаляется вместе с записями трудозатрат, её номер не используется повторно |
| Модуль | `DELETE /projects/{project_id}/modules/{module_id}` | Пустой модуль удаляется. Если к нему привязаны задачи, сервис вернёт `409 Conflict` |
| Проект | `DELETE /projects/{project_id}` | Проект удаляется вместе со своими задачами, модулями и досками |

При успешном удалении сервис вернёт `204 No Content`.
После этого восстановить данные через API нельзя, поскольку корзины в сервисе нет.

Чтобы удалить занятый модуль, сначала перенесите задачи в другой модуль
или снимите у них привязку.

Причины ошибок описаны в [разделе об ошибках](../faq.md#errors).
Поля запросов и ответов приведены в [справочнике API](../api/index.md).
