# Репозитории

Репозиторий хранит и загружает агрегат целиком. Агрегат — это набор объектов,
которые должны быть согласованы в одной транзакции. Таблица и сущность не определяют
границу репозитория.

## Как определить границу

- Если инвариант затрагивает несколько таблиц, они входят в один агрегат и один репозиторий.
- Если объект живёт и изменяется независимо, на него ссылаются по id, а не по составу,
  он отдельный агрегат.
- Агрегат берётся минимального размера, которого достаточно для проверки его инвариантов.

## Что делает репозиторий

- Принимает и возвращает доменные типы, не сгенерированные типы API и не строки БД.
- Преобразует ошибки БД в доменные ошибки.
- Не содержит бизнес-правил и не решает, что можно или нельзя.

## Чтение

- Запросы, которые собирают данные из нескольких агрегатов (список, карточка, отчёт),
  идут через отдельный интерфейс чтения, а не через репозиторий агрегата.
- Такой интерфейс возвращает свои типы (проекции), а не агрегаты.
- Отдельную проекцию для чтения заводи, только если её форма отличается от агрегата:
  данные из других таблиц, другой набор полей, вычисляемые значения.
  Если проекция повторяет агрегат поле в поле, возвращай агрегат.
  Параметры запроса чтения (фильтры, пагинация) принадлежат слою чтения, а не домену.
## Интерфейсы и транзакции

- Интерфейс описывается там, где его используют (в usecase), и содержит только нужные методы.
- Границу транзакции задаёт usecase, репозиторий в ней участвует, но не открывает свою.

## Проверка

Перед созданием репозитория ответь: какой инвариант он защищает и что должно
сохраняться атомарно? Если ответа нет, репозитория не нужно.
