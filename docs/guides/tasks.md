# Работа с задачами и проектами

## Изменить описание, приоритет или срок {#update-task}

Сначала получите актуальную задачу:

```sh title="GET /projects/1/tasks/1"
curl http://localhost:8080/projects/1/tasks/1
```

Затем узнайте доступные приоритеты проекта:

```sh title="GET /projects/1/priorities"
curl http://localhost:8080/projects/1/priorities
```

Выберите приоритет из `items` и передайте его `id` в поле `priority_id`.
Запрос назначает приоритет `High`, добавляет описание,
оценку в один час и срок 30 ноября 2026 года.

```sh title="PUT /projects/1/tasks/1"
curl --request PUT http://localhost:8080/projects/1/tasks/1 --json '{
  "title": "Добавить фильтр по цене",
  "description": "Покупатель задаёт минимальную и максимальную цену.",
  "priority_id": 4,
  "module_id": null,
  "estimate_seconds": 3600,
  "due_date": "2026-11-30"
}'
```

В ответе `200 OK` проверьте изменённые поля.

!!! note "Обновление заменяет поля целиком"

    `PUT` требует `title`, `description`, `priority_id` и `module_id`.
    Чтобы сохранить оценку и срок, передайте их текущие значения
    в `estimate_seconds` и `due_date`. Пропущенные поля станут `null`.
    В примере `module_id: null` снимает привязку к модулю.
    Чтобы очистить описание, передайте пустую строку.
    Чтобы убрать оценку или срок, передайте `null` в соответствующем поле.

Ключ, тип и проект задачи при этой операции не меняются.
Для смены статуса используется отдельное действие.

## Сменить статус {#change-status}

1. Получите `GET /projects/{project_id}/tasks/{task_id}/transitions`.
2. Выберите действие из `items` по названию и целевому статусу `to`.
3. Отправьте его `id` в поле `transition_id`
   методом `POST` на тот же адрес.
4. Проверьте новый `status_id` в возвращённой задаче.

Пошаговый пример есть в [быстром старте](../quick-start.md).
Выбирайте переход из списка действий самой задачи.
Справочник статусов проекта не показывает, куда она может перейти из текущего состояния.

Если получен `409 Conflict`, снова прочитайте задачу и её переходы, затем выберите действие заново.
Список переходов отражает состояние задачи на момент запроса.

## Сгруппировать задачи по модулям {#modules}

Создайте модуль в нужном проекте:

```sh title="POST /projects/1/modules"
curl http://localhost:8080/projects/1/modules --json '{
  "name": "Каталог"
}'
```

Сервис вернёт `201 Created` и модуль с `id`.
Укажите этот идентификатор в `module_id` при создании или обновлении задачи.
При обновлении сохраните остальные редактируемые поля, как описано в
[инструкции по изменению задачи](#update-task).

Чтобы получить список модулей, выполните запрос:

```sh title="GET /projects/1/modules"
curl http://localhost:8080/projects/1/modules
```

Чтобы переименовать модуль, отправьте `PUT /projects/{project_id}/modules/{module_id}`
с новым `name`. Задачи останутся в этом модуле.

## Найти задачи по условиям {#find-tasks}

Список задач запрашивается в пределах одного проекта.
Задачи можно отбирать по статусу, модулю, типу и приоритету.

| Фильтр | Как выбрать значение |
| --- | --- |
| `status_id` | Получить статусы проекта через `GET /projects/{project_id}/statuses` |
| `module_id` | Выбрать модуль из `GET /projects/{project_id}/modules` |
| `task_type_id` | Выбрать тип из `GET /projects/{project_id}/task-types` |
| `priority_id` | Выбрать приоритет из `GET /projects/{project_id}/priorities` |

Запрос отбирает задачи в статусе `In Progress` с приоритетом `High`.

```sh title="GET /projects/1/tasks"
curl 'http://localhost:8080/projects/1/tasks?status_id=2&priority_id=4'
```

Все переданные фильтры применяются одновременно.
Задачи возвращаются по возрастанию номера внутри проекта.
Если на странице нет подходящих задач, `items` будет пустым.

Списки проектов, задач и модулей поддерживают постраничную выдачу:

- `limit` — размер страницы от 1 до 200, по умолчанию 50;
- `offset` — число пропущенных записей, по умолчанию 0.

Для следующей страницы увеличьте `offset` на `limit`.
Когда число элементов меньше `limit`, выдача закончилась.
Общее количество записей в ответе не возвращается.
Пока вы читаете страницы, другие запросы могут менять состав списка.

## Переименовать проект {#rename-project}

```sh title="PUT /projects/1"
curl --request PUT http://localhost:8080/projects/1 --json '{
  "name": "Интернет-витрина"
}'
```

Сервис вернёт проект с новым названием.
Ключ проекта и ключи его задач сохранятся.

## Удалить задачу, модуль или проект {#delete}

| Объект | Метод | Результат |
| --- | --- | --- |
| Задача | `DELETE /projects/{project_id}/tasks/{task_id}` | Задача удаляется, её номер не используется повторно |
| Модуль | `DELETE /projects/{project_id}/modules/{module_id}` | Пустой модуль удаляется. Если к нему привязаны задачи, сервис вернёт `409 Conflict` |
| Проект | `DELETE /projects/{project_id}` | Проект удаляется вместе со всеми его задачами и модулями |

Успешное удаление возвращает `204 No Content`.
Корзины и восстановления через API нет.
Чтобы удалить занятый модуль, сначала перенесите задачи в другой модуль
или снимите у них привязку.

Причины ошибок описаны в [разделе об ошибках](../faq.md#errors).
Поля запросов и ответов приведены в [справочнике API](../api/index.md).
