# FAQ

## Задачи

### Почему нельзя передать новый статус

Статус задачи меняется только через переходы, доступные ей в процессе выполнения.
Например, в стандартном процессе задачу нужно сначала взять в работу и только потом завершить.
Для смены статуса получите список таких переходов и выполните нужный.

Пример запроса есть в [инструкции по смене статуса](guides/tasks.md#change-status),
а описание процесса выполнения — в [основных понятиях](concepts.md#workflow).

### Почему после обновления пропал срок или модуль

Обновление заменяет редактируемые поля задачи целиком.
Поэтому `module_id: null` снимает привязку к модулю,
а пропущенные `estimate_seconds` или `due_date` становятся `null`.
Чтобы сохранить их значения, перед отправкой прочитайте актуальную задачу
и включите эти значения в запрос.

Полный запрос приведён в [инструкции по изменению задачи](guides/tasks.md#update-task).

### Почему задача не найдена по номеру из ключа

В ключе `WEB-12` число `12` обозначает номер задачи в проекте,
а запрос к задаче ожидает её `id`.
Эти числа могут различаться, поэтому возьмите `id` из ответа на создание или из списка задач.
Вместе с ним проверьте `project_id`: задача доступна только в своём проекте.

## Модули

### Почему не удаляется модуль

Модуль с задачами удалить нельзя — такой запрос вернёт `409 Conflict`.
Чтобы освободить его, перенесите задачи в другой модуль или установите у них `module_id: null`,
сохранив остальные редактируемые поля. После этого повторите удаление.

## Доски

### Почему задача не видна на доске

Проверьте, что задача принадлежит проекту доски,
а её текущий статус включён в `status_ids` одной из колонок.
Если доска только что создана, колонок в ней ещё нет — сначала их нужно добавить.

Настройка показана в [руководстве по доскам](guides/boards.md#columns).

### Почему статус нельзя назначить двум колонкам

На одной доске статус относится максимум к одной колонке.
Поэтому попытка назначить его другой колонке вернёт `409 Conflict`.
Для переноса сначала исключите статус из прежней колонки.
Если он был единственным, замените её набор статусов или удалите саму колонку.

### Почему перестановка изменила другую доску

Все доски проекта используют общий порядок задач,
поэтому перестановка видна на других досках, где эти задачи находятся в одной колонке.
Подробнее об этом — в [инструкции по изменению порядка задач](guides/boards.md#order).

### Почему задача не перемещается

Для смены статуса нужен переход, доступный задаче сейчас.
Выберите переход, целевой статус которого входит в нужную колонку.
При `transition_id`, равном `null`, задача сохраняет статус,
поэтому переместить её можно только в колонку, которой он уже назначен.

Если `before_task_id` указывает на удалённую задачу, задачу другого проекта
или задачу вне целевой колонки, сервис вернёт `409 Conflict`.
В этом случае прочитайте колонку заново и выберите актуальную задачу для размещения перед ней
либо передайте `before_task_id: null`, чтобы поставить карточку в конец.

## Ошибки API {#errors}

### Что означают коды ошибок

При ошибке сервис возвращает JSON с полями `code` и `error`.
Например, попытка выполнить недоступный переход даст такой ответ:

```json
{
  "code": "conflict",
  "error": "transition is not available from the current state"
}
```

| HTTP-код | `code` | Что проверить |
| --- | --- | --- |
| `400` | `invalid_input` | Обязательные поля, формат значений, доступность типа, статуса и приоритета в проекте, принадлежность модуля |
| `404` | `not_found` | Существование объекта и правильность идентификаторов проекта, задачи, доски и колонки |
| `409` | `conflict` | Доступность перехода и задачи из `before_task_id`, привязку статуса к другой колонке, занятый ключ проекта или модуль с задачами |
| `500` | `internal_error` | Сохраните метод, путь, время и ответ сервиса для разбора ошибки |

### Как повторить запрос после ошибки

После конфликта перехода перечитайте задачу и доступные действия,
чтобы выбрать переход для её текущего состояния.

При сетевой ошибке создания сервис мог успеть сохранить объект.
Прежде чем повторять запрос, проверьте список объектов,
иначе в проекте может появиться ещё одна такая же задача.

Точные параметры методов и ответы доступны в [Swagger](api/index.md).
