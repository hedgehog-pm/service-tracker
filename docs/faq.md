# FAQ

## Задачи

### Почему нельзя передать новый статус

Процесс выполнения определяет, какие переходы доступны из текущего статуса.
Например, в стандартном процессе задачу нужно сначала взять в работу и только потом завершить.
Получите список доступных переходов и выполните выбранный.

Пример запроса есть в [инструкции по смене статуса](guides/tasks.md#change-status).
Стандартный процесс описан в [основных понятиях](concepts.md).

### Почему после обновления пропал срок или модуль

Обновление заменяет редактируемые поля задачи целиком.
`module_id: null` снимает привязку к модулю.
Если не передать `estimate_seconds` или `due_date`, они также станут `null`.
Перед отправкой прочитайте актуальную задачу и включите в запрос значения, которые нужно сохранить.

Полный запрос приведён в [инструкции по изменению задачи](guides/tasks.md#update-task).

### Почему задача не найдена по номеру из ключа

В `WEB-12` число `12` — номер задачи в проекте.
Запрос к задаче ожидает её `id`, который возвращается при создании и в списке задач.
Он может отличаться от номера.
Проверьте также `project_id`, потому что задача доступна только в своём проекте.

## Модули

### Почему не удаляется модуль

Если в модуле есть задачи, удаление вернёт `409 Conflict`.
Перенесите задачи в другой модуль или установите у них `module_id: null`,
сохранив остальные редактируемые поля, затем повторите удаление.

## Ошибки API {#errors}

### Что означают коды ошибок

Ошибки возвращаются в JSON с полями `code` и `error`.
При попытке выполнить недоступный переход ответ будет таким:

```json
{
  "code": "conflict",
  "error": "transition is not available from the current state"
}
```

| HTTP-код | `code` | Что проверить |
| --- | --- | --- |
| `400` | `invalid_input` | Обязательные поля, формат значений, доступность типа и приоритета в проекте, принадлежность модуля |
| `404` | `not_found` | Существование объекта и правильность `project_id` и `task_id` |
| `409` | `conflict` | Не занят ли ключ проекта, доступен ли переход сейчас, нет ли задач в удаляемом модуле |
| `500` | `internal_error` | Сохраните метод, путь, время и ответ сервиса для разбора ошибки |

### Как повторить запрос после ошибки

После конфликта перехода перечитайте задачу и доступные действия.
Если создание завершилось сетевой ошибкой и результат неизвестен, сначала проверьте список объектов.
Повторный запрос создания задачи может создать ещё одну задачу.

Точные параметры методов и ответы доступны в [Swagger](api/index.md).
