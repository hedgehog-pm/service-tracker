# Usecase

Usecase выражает действие над доменом. Группируй их по сущностям, а не по операциям.

## Простые операции

Операции без собственной логики (получить, список, удалить, простое обновление
полей) собираются в один пакет на сущность. В нём один тип Usecase с методами
`Get`, `List`, `Create`, `Update`, `Delete` и один интерфейс репозитория с нужными методами.

Простая операция только передаёт вызов в репозиторий и возвращает результат.

## Сложные операции

Вынеси операцию в отдельный пакет, если выполняется хотя бы одно условие:

- она использует зависимости, которых нет у остальных операций сущности
  (другой репозиторий, внешний клиент, часы);
- в ней есть правило, которое нельзя выразить схемой API или ограничением БД
  (проверка принадлежности, выдача номера, переход состояния);
- она охватывает несколько агрегатов или требует транзакции между ними.

Если условий нет, операция остаётся методом в пакете сущности, даже если кода в ней много.

## Интерфейсы

Интерфейс репозитория объявляется в пакете usecase и содержит только методы,
которые этот пакет вызывает. Параметры методов именуются.

## Проверка

Перед созданием нового пакета ответь: что в этой операции отличается от остальных
операций сущности — зависимости, правило или транзакция? Если ничего, пакет не нужен.
